# 디자인 계약을 어디까지 넓힐 것인가 — 범위 표

작성 2026-09-15. `docs/DESIGN-FOUNDATION-PLAN.md`의 "Next DS implementation gates" 2번을 실제 작업 범위로 내리는 문서. **취향이 아니라 두 가지 증거**로 정했다 — OmD 코퍼스 440개가 실제로 쓰는 역할, 그리고 우리 렌더러가 지금 하드코딩하고 있는 값.

## 지금 계약이 담는 것

```
primary(accent) · background · foreground · radius · font(serif|sans)
```

다섯이다. OmD의 `design-system-graph-v2` 스키마는 `tokenMap`이 열려 있어(`^[a-z][a-z0-9.-]*$` → DTCG 토큰) 역할 목록을 규정하지 않는다. **무엇이 필요한지는 스키마가 아니라 코퍼스가 말한다.**

## 증거 1 — 440개 브랜드가 실제로 정의하는 역할

`design-md/*/DESIGN.md`의 색 역할 섹션에서 이름을 뽑아 의미 계열로 묶은 결과다.

| 계열 | 파일 수 | 비율 | 우리 상태 |
|---|---:|---:|---|
| canvas | 372 | 84% | ✅ `background` |
| ink | 285 | 64% | ✅ `foreground` |
| **muted** | 278 | **63%** | ❌ 없음 |
| **border** | 264 | **60%** | ❌ 없음 |
| **surface** | 218 | **49%** | ❌ 없음 |
| danger | 88 | 20% | ❌ 없음 |
| on-primary | 75 | 17% | 🟡 `onColor()`로 계산만 |
| success | 78 | 17% | ❌ 없음 |
| link | 57 | 12% | ❌ 없음 |
| primary-hover | 12 | 2% | ❌ 없음 |

우리가 없는 것 중 **muted(63%)·border(60%)·surface(49%)가 가장 흔하다.** 절반 이상의 브랜드가 정의하는 것을 우리는 받지 못하고 버린다.

## 증거 2 — 렌더러가 이미 칠하고 있는 것

`render.ts` · `pattern-render.ts` · `page.css` · `patterns.css`에 **하드코딩된 색이 29곳, 14종**이다.

| 값 | 횟수 | 무엇 |
|---|---:|---|
| `#ba3030` | 6 | **위험(danger)** — notice 컴포넌트의 오류 상태 |
| `#fff` | 6 | 카드 바탕 / primary 위 글자 |
| `#e9e7df` `#eeece5` `#d9d4c8` | 5 | **surface · border** 회색들 |
| `#187345` | 2 | **성공(success)** |
| `#a76600` | 2 | **경고(warning)** |

이게 결정적이다. **상태 색은 이미 화면에 그려지고 있다.** 다만 상수라서 디자인 시스템을 따라가지 못한다. 토스를 가져와도 notice는 계속 `#ba3030`으로 붉다.

## 범위 표

### ① 구현한다 — 렌더러·인스펙터·JSON 검증·내보내기·DESIGN.md 다섯 곳에 함께

| 토큰 | 근거 |
|---|---|
| `surface` | 코퍼스 49% · 하드코딩 회색 12곳 |
| `border` | 코퍼스 60% · 하드코딩 8곳 |
| `muted` | 코퍼스 63% · 보조 텍스트 회색 3곳 |
| `on-primary` | 지금은 `onColor()`가 계산 → **계산을 기본값으로 두되 덮어쓸 수 있게** |
| `danger` | notice가 이미 `#ba3030`을 칠한다 |
| `success` | 이미 `#187345` |
| `warning` | 이미 `#a76600` |

일곱이다. **전부 "이미 화면에 존재하는 것을 계약에 연결하는" 작업**이지 새 개념을 들이는 게 아니다. 그래서 올리는 즉시 가져온 디자인 시스템이 화면을 바꾼다.

### ② 실어만 나른다 — 저장하고 그대로 내보낸다

`link`(12%), `primary-hover`(2%), 그리고 **스키마가 허용하는 나머지 모든 키**. 임포트한 `tokenMap`을 원본 그대로 보관하고 내보낼 때 다시 쓴다. 화면엔 영향이 없지만 출처가 보존된다.

렌더링하지 않는 이유는 명확하다 — 그것을 쓰는 컴포넌트가 없다. 정적 내보내기에 hover 상태가 없고, 링크로 스타일링되는 블록이 없다. **쓰지 않는 토큰을 받아놓고 받았다고 말하는 것이 가장 나쁘다.**

### ③ 버린다

**없다.** `tokenMap`은 열린 스키마이므로 모르는 키는 버리지 않고 ②로 나른다. 버리는 것은 스키마 위반 값(형식 불일치)뿐이고, 그때는 조용히 버리지 않고 임포트 결과에 몇 개를 못 읽었는지 적는다.

## 타이포그래피 — 가장 얇은 곳

지금 계약의 서체는 `font: 'serif' | 'sans'` **한 글자**다. 스키마의 `typeRole`은 `id · usage · family · size · weight · line_height · tracking`을 갖는다.

이 얇음이 이미 대가를 치렀다. 2026-09-15 평가 Run 3에서 모델이 찾아낸 한글 서체 결함 — 라틴 전용 폴백 때문에 한국어 페이지가 디자인 시스템의 성격을 전혀 갖지 못하던 것 — 은 **언어별 서체를 표현할 자리가 계약에 없었기** 때문이다. 폴백 체인으로 막았지만 근본은 이것이다.

**①로 올릴 것**: `heading` · `body` · `caption` 세 역할, 각각 `family` · `size` · `weight` · `line_height`. 지금의 `font`는 `heading.family`의 축약으로 남긴다(기존 프로젝트 호환).

## 작업 순서

| | 내용 | 규모 |
|---|---|---|
| D1 | 모델·검증: 토큰 7개 + 타입 역할 3개를 `DesignSystem`에, `parseProject` 검증, 마이그레이션(없으면 지금 하드코딩 값이 기본값) | 2h |
| D2 | 렌더러: 하드코딩 29곳을 `var(--surface)` 등으로 교체. **이 단계에서 화면이 바뀌면 안 된다** — 기본값이 현재 상수와 같아야 한다 | 2h |
| D3 | 인스펙터 편집 UI + DESIGN.md 읽기/쓰기 확장 + 내보내기 | 2h |
| D4 | OmD `tokenMap` 임포트: ①은 투영, ②는 보관, 못 읽은 것은 개수 보고 | 2h |

D2의 "화면이 바뀌면 안 된다"가 안전장치다. 기본값이 현재 상수와 정확히 같으면, 회귀 없이 배선만 끝난 상태가 만들어지고 그 다음부터 디자인 시스템이 실제로 화면을 움직인다.

## 확인 방법

- 토큰 7개 각각: 값을 바꾸면 렌더된 페이지가 바뀌는지 — `aphrodite_get_render`로 전후 이미지를 비교한다(이제 에이전트가 볼 수 있다).
- 임포트: 토스 DESIGN.md를 넣으면 `surface #f2f4f6` · `border #e5e8eb` · `muted #8b95a1`이 실제로 적용되는지. 코퍼스 440개가 회귀 픽스처가 된다.
- 하드코딩 0: 렌더러에 남은 색 상수를 세는 테스트.
